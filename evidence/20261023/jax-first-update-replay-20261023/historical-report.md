# 首次非零更新：固定数据、权重与 Adam 状态的诊断

**本次受控实验支持：首次非零更新的 loss 突增，主要由原学习率 2e-4 对当前预训练模型、固定 batch 和 Adam 状态过大造成。训练精度也引入可测的梯度及更新差异，但两条路径的 loss 都在大步长下大幅上升，在小步长下下降。**

不能据此把之前 40 步输出的 32.26% 差异全部归于学习率；改善后的完整训练及推理验收仍需另做。

## 学习率对照：所有 loss 都用同一个 FP32 前向评价

固定窗口 [2,3]，两个 batch=1 的微批次，梯度累计2。每档均从同一份原始权重和同一 Adam 状态独立更新一次。

更新前共同 FP32 loss 为 **1.3054049015**。

| 学习率 | FP32 训练更新后的 loss | RNE＋XF32 训练更新后的 loss | 相对更新前的变化 |
|---|---:|---:|---|
| 0 | 1.30540490 | 1.30540490 | 参数及 loss 不变 |
| 3e-7 | 1.30096334 | 1.30096239 | 两组均下降约 0.34% |
| 2e-6 | 1.29057515 | 1.29054981 | 两组均下降约 1.14% |
| 2e-5 | 1.81343389 | 1.81389284 | 两组均上升约 38.9% |
| 2e-4，原首次非零学习率 | 28.48362732 | 28.49550819 | 升至约 21.82 倍 |

固定 batch 后仍复现 loss 从约1.3上升到约28.5，排除了“必须由换 batch 才能导致这次突增”的解释。仅降低学习率就改变了更新对 loss 的作用方向。即使降为原来的十分之一（2e-5），本样本上的更新仍使 loss 上升。

在 2e-4 下，两种训练精度的更新后 loss 仅相差约 **0.04171%**，远小于各自相对更新前的上升幅度。这一结论专指当前受控的首步 loss 行为，不代表后续独立轨迹始终接近。

## 梯度与参数变化

| 项目 | 相对 L2 差异 |
|---|---:|
| 同参数点，RNE＋XF32 梯度对 FP32 梯度 | 3.507320% |
| 同一 Adam 状态下，两种梯度产生的更新方向 | 1.740785% |
| FP32 两次重复计算梯度 | 0.000945% |
| RNE＋XF32 两次重复计算梯度 | 0.349230% |
| 本次 FP32 梯度对历史第2次更新的 FP32 梯度 | 0.001025% |

FP32 / RNE 梯度范数分别为 20.509523 / 20.592092，梯度余弦相似度为 0.99939547。当前梯度范数均低于裁剪阈值32。跨精度差异高于本次重复运行的差异，说明训练精度确实会改变梯度；RNE 路径本身也存在可见的重复运行差异。各两次重复只用于观测波动量级，不能给出稳定的统计置信区间。

| 学习率 | FP32 实际参数变化 L2 范数 | RNE 实际参数变化 L2 范数 | 两条实际更新的相对 L2 差异 |
|---|---:|---:|---:|
| 3e-7 | 0.001340710 | 0.001340506 | 1.759606% |

降低学习率缩小了实际参数变化，也缩小了两种精度之间的绝对参数差异，但并未改变固定参数点上已经测出的梯度差异。上述“更新差异”以参数变化量为分母，不应与以完整参数为分母的差异混用。

## 起点与方法

- 官方完整 GraphCast：0.25°、13层，源码 `08cf73625c9d12bd9aaa038868bcb2fe488f2a22`，原始官方预训练权重。
- 单卡 BW1100（驱动名称 BW1200），物理 GPU 12 / `0000:b0:00.0`，固定镜像 `sha256:919cf075fadd5fab21b2ea5978374be00caf1db7d6f02fc90846633c4c4bd546`。
- JAX/JAXlib `0.6.0+das.opt1.dtk2604`；FP32 参数、激活、优化器状态；不使用 BF16。RNE 路径与原训练一样，在前向、反向和重计算的 GEMM 两侧做 RNE 后调用 rocBLAS XF32。
- 单步训练，种子27，原第2次更新的数据窗口 [2,3]，固定数据文件 SHA256 `b6af9df3d83d132e1247004f761150d3e5e1bb423e5f99d7060bf9ee618e7ee8`。
- 原第1次更新学习率为0，参数未动但 Adam 历史状态已改变。使用经过校验的历史 FP32 第1次梯度重建 count=1 的 Adam 状态，**两条路径均从这同一状态出发**。有意排除了原 RNE 第1次更新所产生的不同优化器状态。
- 原样保留 AdamW：beta=(0.9,0.95)、eps=1e-8、矩阵权重衰减0.1、全局梯度裁剪32。所有学习率都从共同起点分叉，不串行累计。
- 先分别重复两次计算梯度；学习率实验使用各自第一次梯度。共同前向以 FP32 评价所有更新前后的 loss，同时保留 RNE 前向评价结果。
- 结束时重新核验原始参数、优化器状态和 batch 均未改变；零学习率分支参数逐元素不变。每个微批次的反向调用402次GEMM，每次累计梯度计算804次。

第一次采用按需扩展显存池，在前向评估后申请72GiB反向临时空间失败，目录 `run` 保留退出码1和完整日志。之后仅改为预分配70%显存池，完整实验位于 `run-preallocated`，退出码0；三项共同起点校验值与第一次一致。显存分配方式调整不改变模型、数据、学习率或精度算法。GPU 已释放。

## 后续判断与建议

优先调整继续训练的学习率日程。当前固定样本上，3e-7和2e-6均改善首步 loss；2e-6只是本次测试的候选值，不是已验证的长期最优学习率。

下一轮可在这一小步长范围内验证连续更新是否稳定，再执行完整38次训练及40步推理验收。需要保留独立验证样本及中间 checkpoint，避免只看训练 loss。

本轮尚未验证降低学习率后是否满足整体/Z500的5%要求，也没有分别拆分 RNE 前向、反向精度或原第1次优化器状态差异对长期训练的影响。原有训练结果及推理 baseline 均保持不变。
