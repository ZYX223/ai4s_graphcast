# XF32 输入舍入

## 已验证的问题与处理

原始海光 XF32 在受控实验中完成 40 步后，整体差异约 22.79%。原生矩阵探针支持其输入降低精度时呈现向零截断特征；差异被自回归反馈放大，Mesh2Grid 节点更新 MLP 较敏感。

当前方案对原生 GEMM 两个输入先做最近偶数舍入（RNE），将 FP32 的 23 位显式小数舍入到 10 位，仍以 FP32 存储，再调用 rocBLAS XF32。原始输入和 checkpoint 保持不变，舍入结果存入设备临时缓冲区，与 GEMM 使用同一 stream。

实际核心代码在 [rne_kernel.hip](../kernels/xf32_rne/rne_kernel.hip)：

```cpp
uint32_t bits = __float_as_uint(src[offset]);
if ((bits & 0x7f800000u) != 0x7f800000u)
  bits = (bits + 0x00000fffu + ((bits >> 13) & 1u)) & 0xffffe000u;
dst[offset] = __uint_as_float(bits);
```

加上半个量化间隔减一，再加保留部分最低位，最后清除低 13 位，共同实现“最近值，中点取偶数”。结果低 13 位为零，随后 XF32 再截断这些位不会继续改变普通有限输入。NaN/Inf 保留；极大有限值可能进位为 Inf，极小数可能成为带符号零。详解和可运行示例见 [中文 Demo](../examples/rounding/README.txt)。

## 接入位置

官方 GraphCast 和 JAX 源码没有为此修改。`xf32_rne_router.cc` 在 rocBLAS 调用边界接入：

1. 识别 84 个运行时 GEMM 对应的冻结权重指纹，兼容两个存储方向。
2. 设置并回读原生数学模式：FP32 或 XF32。
3. RNE 模式下对 A、B 分别启动舍入核，然后调用原生 GEMM。
4. 恢复调用者原先的数学模式，并记录调用计数。

每步 RNE 模式有 84 次 GEMM、168 次额外舍入核启动。路由库通过 `dlsym` 拦截处理 XLA 直接从动态库句柄查符号的情况。`weights.tsv` 和 `weights.json` 已纳入本项目，并绑定原始 checkpoint；正式运行不再依赖早期敏感层实验目录。

H100 通过 JAX `tensorfloat32` 配置执行 TF32，保留 FP32 存储。独立矩阵探针、优化 HLO 与实际 TF32 GEMM 内核跟踪见 [执行证据](../evidence/20261016/tf32-evidence.json)。海光各模式也使用 JAX `tensorfloat32` 请求，但实际 GEMM 精度由路由库逐调用设置、核查；其中 FP32 对照显式使用原生 FP32 模式。

## 构建和验证

启动海光探针或基准测试时，自动从仓库源码重新编译共享库，不使用历史目录中的预编译文件：

```bash
/opt/dtk/bin/hipcc --offload-arch=gfx938 -O2 -fPIC -shared \
  kernels/xf32_rne/xf32_rne_router.cc kernels/xf32_rne/rne_kernel.hip \
  -o libxf32_rne_router.so -lcrypto -ldl -pthread
```

构建记录包括命令、编译器版本、源码及产物 SHA-256。设备探针测试随机位型、正负数、中点奇偶、NaN/Inf、跨列步长和原输入不变；同时检查 RNE 路由与显式预舍入一致、模式切换后 FP32 恢复。

## 结果与限制

受控精度实验中，全量 RNE 将第 40 步整体差异相对匹配 FP32 从 22.788808% 降至 1.765637%，降低约 92.25%。只启用敏感节点 MLP 时，对应差异从 6.092202% 降至 0.289592%。这些属于原始受控实验，不能与独立三轮性能统计混为一轮。

该实现面向当前单设备、串行调用、固定模型和权重，关闭图捕获；尚未融合舍入或缓存预舍入权重。它不是通用 rocBLAS 替代库，不用于完整训练或未知形状/权重。运行发现未知权重会停止。两平台均未提供逐指令 ISA 反汇编，已有证据范围以实验记录为准。
