## 1. 两层评估与首版边界

首版实现 checkpoint-only 评估：NV 与国产平台训练出的模型，放到相同的、已验证的 Native 推理环境，以相同严格 FP32 精度和 baseline 模型配置运行。优先复用 H100 Native 环境；H100 是控制条件，不是数学算法的硬件要求，资源不足时不静默换环境。

这一步仅隔离训练产生的模型差异，严格 FP32 评估不改变 TF32 训练要求。后续再单独评估国产 checkpoint 在本平台 TF32/HF32 + FlagGems 的实际训练/推理链路；后者的下降不能全归因于训练。首版不添加第二套平台调度框架，不自动启动所有平台。

不采用仅比较 loss 的方案，因为它不测量天气技巧；也不把两份 checkpoint 各自平台推理的分数直接当作纯训练结论，因为其中混入了推理实现差异。

## 2. 可比较的训练产物

参考必须是与候选按同一训练方案得到的 NV checkpoint。历史预测 NPZ、small-1deg loss CSV、未训练的官方初始化权重均不能替代。初始化权重可作为辅助控制，但不参与该训练迁移验收门槛。

预检提取并记录：模型配置、初始化参数指纹、训练数据及归一化统计内容指纹、采样规则/seed、有效全局 batch、优化器与学习率计划、rollout 课程、optimizer update、数据游标及有效样本预算。评估的是预先约定训练阶段，不依测试结果挑选最佳 checkpoint。

比较训练语义字段，不逐字比较整个 resume_contract：平台、backend、设备路径与并行拓扑本来就可能不同，必须记录但不能一律判为不兼容。必要的可比性证据缺失或训练预算不同，返回未验证，不授予正式通过。已有 checkpoint 不因缺少新证据而被覆写；允许关联有指纹的原始训练运行记录补证，但不从名称猜测元数据。

只读取训练产物，不恢复 optimizer 或 RNG 到评估进程。使用严格的参数键/shape 检查，不忽略缺失参数。真实完整训练 checkpoint 的序列化加载必须回归测试，不能只用手工构造的 model_state 字典验证兼容性。仅加载用户指定、来源可信的本地 checkpoint；不全局放宽 PyTorch 的加载安全策略。

## 3. 固定测试案例与物理量

一份版本化 JSON 评估配置承载协议与案例清单。案例具有唯一 ID、起报时刻、初始输入、forcing、target template、ERA5 真值及内容指纹。正式首组为预先固定的 12 个案例、覆盖一年；具体日期和资产必须由真实可用数据填写，不能伪造。单案例试跑可报告指标，但状态为 pilot，不冒充 12 案例正式验收。

所有测试窗口与训练窗口隔离，包含预测所需输入历史及完整未来真值。对于继承的预训练权重，记录其已知训练时间范围，不能把“与本次微调不重叠”宣称为“与全部预训练不重叠”。

两份 checkpoint 使用完全相同的案例、初始状态和 forcing，执行自由自回归。未来 ERA5 只供评分；target template 只供结构/坐标，未来天气真值不能回写 state。辅助 forcing 必须是既定推理流程允许使用的输入。

主变量为 `geopotential` 的 500 hPa 层及 `2m_temperature`。验证变量映射、单位、压力层、网格、经纬度顺序、起报/有效时刻；Z500 的位势与位势高度不能按同一单位直接混用。只有明确、可记录的单位转换可接受，不做隐式裁剪、插值或 inner join 丢弃数据。

气候态按 PPT 指定的 CMA-RA V1.5、1991–2020、六小时口径预先准备，必须记录来源、年月范围、变量单位、网格及时间索引规则。若需再网格化，应作为可追溯的离线数据准备，不藏在评分函数里。跨闰年按明确的月/日/小时映射处理，禁止把不同年份的裸 dayofyear 当作无条件等价。缺少对应日期或闰日策略时拒绝该正式评估。归一化均值不能代替气候态；未获批准不换成 ERA5 气候态。

## 4. 指标协议

### 空间评分

对每个变量 v、案例 c、时效 h，以物理单位数据计算 FP64 指标。设预测 F、真值 O、气候态 C，定义 f = F - C、o = O - C。

采用全球规则经纬网格的纬度球面单元面积权重，复用现有纬度边界积分方式；权重协议明确记录为 `spherical_latitude_cell_area`，不声称是另一种未核实的权重标准。记加权空间平均为 E_w：

```
ACC[v,c,h] = E_w[(f - E_w[f]) * (o - E_w[o])]
             / sqrt(E_w[(f - E_w[f])**2] * E_w[(o - E_w[o])**2])
RMSE[v,c,h] = sqrt(E_w[(F - O)**2])
```

这是中心化距平 ACC。现有脚本默认的未中心化距平 ACC 保持不变，新增显式协议 `training_checkpoint_weather_skill.v1` 选择新行为；历史诊断输出、默认参数与算法不得静默改变。

NaN/Inf、空网格或零距平方差均是无效结果，不以加 epsilon 或跳过该记录制造可用分数。每个案例/变量/时效都需保留记录，不先跨案例平均天气场再算相关系数。

### 时间和案例汇总

协议显式列出所需 lead_hours 及两个不重叠窗口。初始正式协议为六小时间隔：6–72 h 为短期，78–240 h 为中期；短期和中期各占 0.5。

```
S[v,c] = 0.5 * mean(ACC[v,c,h] for h in short_leads)
       + 0.5 * mean(ACC[v,c,h] for h in medium_leads)
S[v] = mean(S[v,c] for c in all_required_cases)
```

窗口内、案例间分别等权。先得到参考与候选的 S[v]，再计算两者的相对变化；不平均逐时效百分比，也不平均逐案例百分比。

通用运行和评分代码不固定 40 步：由配置中的时效集合、step_hours 与预报长度决定推理步数，并校验整除、连续性和完整覆盖。10 天/6 小时的 40 步只是该协议配置的结果。更短轨迹可测量，但不能满足该 10 天正式验收；更长轨迹保留额外记录，不能偷偷改变验收窗口。不得丢弃缺失时效后重新归一化权重。

### 已确认的 5% 判定

```
D[v] = 100 * (S_reference[v] - S_candidate[v]) / S_reference[v]
pass = D[Z500] < 5 and D[t2m] < 5
```

改善产生负 D，不判失败。阈值为严格小于，不四舍五入后判定；恰好 5% 不通过。例：0.80 对 0.77 下降 3.75%，0.80 对 0.75 下降 6.25%。两个变量分别判定，无跨变量平均。

相对门槛只适用于正且足够稳定的参考评分。正式运行配置必须显式给出经基线资格检查确认的 `minimum_reference_score`（严格大于零）；不在代码中猜测一个气象学阈值。未提供该资格条件，或任一参考评分不高于该下限，仍可输出原始 ACC/RMSE，但结论为 `unverified_reference`，不自动通过。这是正式运行输入要求，不修改用户确认的 5% 门槛。

逐时效/逐案例 ACC、RMSE、ACC 绝对差和 RMSE 相对变化作为解释信息。首版不新增未批准的 RMSE 门槛，也不把 normalized max/RMSE 输出一致性指标混入天气技巧通过条件。

## 5. 最小代码结构与运行方式

- 新增 `ai4s/graphcast/scripts/training/diagnose_training_checkpoint.py`，仅负责配置/资格预检、顺序调用已有推理入口、汇总与发布结果。提供不分配加速器的 dry-run；命令显式指定两份 checkpoint、评估配置和输出目录。
- 扩展 `ai4s/graphcast/scripts/inference/evaluate_forecast_skill.py` 的显式协议选择，复用坐标/单位/finite/面积权重逻辑，并能保留逐案例记录。旧默认协议和旧 CLI 均兼容。聚合使用可独立测试的纯函数，不依赖设备。
- 新增 `ai4s/graphcast/configs/training/checkpoint_weather_skill.json` 作为协议模板；真实数据路径、案例指纹和参考资格来自运行配置。模板本身不构成已可正式运行的证据，预检必须明确拒绝资产或资格不全的正式运行。
- 复用 `run_operational_40step_inference.py` 的 checkpoint 参数提取、设备常驻自由自回归及 trajectory-output。不复制模型或另造一条训练专用推理循环；仅在真实 checkpoint 加载回归证明需要时作局部兼容修改。

两个 checkpoint 依次运行，避免同时驻留增加显存。Native 运行使用明确的既有 backend 控制及干净子进程，并从实际运行报告核对 backend、精度、模型配置和源码指纹；不能只信启动参数。评估不恢复训练状态，也不在正在运行的训练进程内执行。

先逐案例产出轨迹，再在 CPU 上逐变量/时效评分，不一次堆叠所有案例的完整全球预测进内存。允许复用已有轨迹，但必须核对 checkpoint、案例、推理实现、精度与协议指纹；缓存目录同名不足以证明可复用。首版不新增长期服务、任务队列或平台自动部署。

诊断包含逐时效 D2H 与输出 I/O，必须沿用并核查 `performance_eligible=false`；不把它的耗时写入正式 E2E/MFU 性能表。硬件性能测试仍是独立流程。

## 6. 输出、失败语义与数据保护

结果包含机器可读 JSON 汇总和逐案例/变量/时效 CSV，关联原始推理报告与轨迹。记录代码版本/内容指纹、checkpoint SHA256、训练可比性检查、推理环境/精度、统计和气候态来源、案例与时效完整性、两变量 S/D/判定。

区分 `pass`、`fail_skill`、`invalid_prediction`、`incomplete`、`unverified_reference`、`incomparable_training` 和 `pilot`。只有完整正式集合、可比较训练、合格参考、有效预测且双变量满足门槛才能 `pass`；所有其他状态在机器可读结果中均非通过，正式验收命令返回非零。

检查输入和输出路径互不覆盖。缺省拒绝覆盖已有结果，复用先查指纹；原子发布结果，崩溃遗留的部分文件不构成完成记录。权重、气候态、ERA5、完整轨迹和实测输出均不进入 Git。

12 案例是固定工程验收集合，不等同于对全部天气类型、起报时刻和训练随机性的普遍保证。报告必须保留逐案例离散情况，不把平均达标扩大为全面等价。

## 7. 验证要求

1. 纯 CPU 手算验证：中心化/未中心化区别、面积权重、完美相关/反相关、常量和非有限场、单个案例异常不得被丢弃。
2. 聚合验证：短中期 0.5/0.5、窗口内等权、案例间等权；先平均评分再算下降；5% 严格边界、改善、低参考评分与双变量独立门槛。
3. 数据契约验证：任意 rollout 长度、重复/遗漏/错位时效、缺案例、单位/层次/坐标不符、valid_time 不一致、闰年气候态、训练/测试重叠和参考资格缺失。
4. 集成验证：新训练流程真实保存的完整 checkpoint 可供推理加载；同一 checkpoint 自比较为零差异；禁止静默宽松加载。小 tensor 测试仅证明软件行为，不是天气验收。
5. 编排验证：dry-run 不占用设备，Native 运行无 FlagGems 污染，来源不匹配的轨迹不能复用，子进程失败/中途退出不发布通过，诊断计时永不进入性能结果。
6. 回归现有推理、天气指标和训练测试，确保旧诊断默认值与历史协议不变。
7. 设备阶段另行开展：两份合格 checkpoint 的单案例完整 10 天试跑，再完成冻结的 12 案例正式验收。真实案例、指定气候态和 NV 训练参考未资格确认前，不承诺已有通过结果。
